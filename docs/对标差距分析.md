## 三、最关键的结论：一处**结构性差距**

前面 21 项里，绝大多数是产品功能，写代码能补。但有一项不是：

> **他们自建/微调了渲染模型与管线**（「AI精准渲染」「SU白模直出」），结构服从靠的是**专用条件控制**——线稿条件、深度图、ControlNet 式的几何约束。我们调的是**中转站的通用 `gpt-image-2`**，它没有结构条件通道。

所以我们的结构保真只能走这条**软路径**：

```
裁剪到只剩立面 + 黑底转白底 + 视觉模型读出结构清单 + 提示词硬约束 + 出图后质检重出
```

这套我们已经全部做完了，实测能把「完全不看 CAD」拉到「逐条对上」。但它的**上限受模型限制**：模型仍然可能少画一块层板。要突破这个上限只有两条路：

1. **换成支持结构条件的服务**：本机自建 ComfyUI + Flux/SDXL + ControlNet（线稿/MLSD 直线检测条件），结构服从度会有质变 —— 但要装环境、下模型，且需要一张能跑的显卡。
2. **中转站若有带 mask/线稿条件的模型**（部分站会转 `flux-kontext`、`seededit` 这类编辑模型），换模型即可 —— 成本最低，**建议先问你的中转站**。

## 四、我建议的补齐顺序（针对**柜体下单图**这个真实场景）

不必对标他们的全流程（场地规划 → 3D → 视频），那些和你的业务无关。真正该按这个顺序补：

| 优先级 | 要补的 | 理由 | 状态 |
|---|---|---|---|
| **P0** | **一键换光 / 换角度**（在成品上继续改） | 客户最常提的就是「换个光看看」「换个角度」 | ✅ 已完成（8 个一键操作） |
| **P0** | **历史记录 + 参数复用** | 出完图参数不该丢，点一下整套还原 | ✅ 已完成（含坏文件自愈、条数上限） |
| **P1** | **材质库** | 板材/色卡裁好存起来，下次直接点 | ⬜ 待做 |
| **P1** | **画布：多图接力** | 结果栏保留本轮全部候选，点任意一张作为下一轮输入 | ⬜ 待做 |
| **P2** | **局部重绘（蒙版）** | 功能价值最高，但需要画笔交互 + mask 上传 + 结果对齐 | ⬜ 待做（工作量最大） |
| **P2** | 立面组图（一次出多个立面） | 上传的 CAD 常含正立面+侧剖+俯视，可以一次全出 | ⬜ 待做 |
| **P2** | 展板拼版（本地 Pillow） | 已出图 + 彩平 + 色卡 + 标题排版，不花生成费 | ⬜ 待做 |
| **P3** | 预设库可视化编辑 + 示例图 | 让预设能自己加、能看效果 | ⬜ 待做 |
| **⛔** | 图转3D / 视频 / 参数滑块 | 受模型能力限制，中转站没有对应能力 | ⛔ 做不到 |

## 五、我们相对他们的**优势**（别忘了）

| 维度 | 说明 |
|---|---|
| **成本** | 用你会话自带的模型做读图/质检/润色，**这部分不花钱**；出图只付中转站的单价。他们是点数计费，全流程都在扣点 |
| **读图/质检不额外付费** | 自动质检用的是 DSH 的多模态模型，不是付费的图像模型 |
| **可编程 / 可扩展** | 面板与 Agent 走同一条命令，你可以直接在对话里用 `/ai-render` 批量刷图；也能让 Agent 自己决定风格与迭代 |
| **数据本地** | 图纸、结果、密钥都在本机，不上传他们的云 |
| **贴业务** | 预设是照柜体场景写的（13 个家居风格、柜体结构锁死、施工图元素清除），通用平台要自己拼 |
