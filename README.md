# AI 效果图 · DSH 插件

**通用的 AI 效果图工作台**：导入**底图** + **参考图**，按参考图的材质、颜色与风格生成写实效果图。

底图**不限于柜体**——立面施工图、手绘线稿、SU/3D 模型截图、现场实拍照片、平面布置图都能出图；柜体下单图只是其中一种用法。

- 插件包：`@local/dsh-ai-render`
- 出图通道：**火山方舟 即梦 Seedream**、**阿里云百炼 通义万相**、**OpenAI 兼容中转站**、**Google Gemini（本机 agy）**，面板里可实时切换

### 能力一览

| 维度 | 内容 |
|---|---|
| **11 种操作** | 立面/施工图、手绘线稿、模型图、实拍照片、平面图（彩平）、平面→立体户型、平面→透视效果图、分析图、风格迁移、换视角、文生图 |
| **29 个风格预设** | 家居 13 + 彩平 5 + 轴测 4 + 分析图 4 + 概念 3，按操作自动切换 |
| **机位三维度** | 水平角度 8 方位 × 垂直角度 4 高度 × 取景距离 3 档，另有 6 个常用机位 |
| **出图比例** | 跟随底图 / 1:1 / 3:2 / 2:3 / 4:3 / 3:4 / 16:9 / 9:16 |
| **智能体能力** | AI 读图出结构 · 出图后自动质检并修正重出 · 大白话润色成专业话术 · 8 个结果一键操作 · 历史记录与参数复用 |

## 安装（给新用户）

### 1. 把插件放到本机

```bash
git clone https://github.com/cqdjyjy/dsh-ai-render.git ai-render
```

### 2. 链接进 DSH profile

DSH profile 目录：Windows 默认 `%USERPROFILE%\.dsh\profiles\desktop`。

用 DSH 自带的插件管理器安装这一份**本地目录**（把下面的路径换成你 clone 出来的绝对路径）：

```
plugin_manager install_bundle  target = link:<ai-render 的绝对路径>
```

或者手工加依赖：

```bash
pnpm add "@local/dsh-ai-render@link:<ai-render 的绝对路径>"
```

### 3. 启用并刷新

- 在 DSH 的插件管理里启用 `ai-render`
- **刷新页面（Ctrl+R）**，右侧边栏就会出现「AI 效果图」标签页

### 4. 配置出图通道

面板右上角 **设置** → 选一个通道填 Key：

| 通道 | 需要什么 | 建议 |
|---|---|---|
| **火山方舟 即梦 Seedream** | 火山方舟 API Key | **国内直连，首选** |
| **阿里云百炼 通义万相** | 百炼 DashScope API Key | 国内直连 |
| **OpenAI 兼容中转站** | 中转站 base URL + Key | 支持 gpt-image 系列，可锁定结构优先 |
| **Google Gemini** | 本机装好并登录 `agy` | 可选，环境要求高（见下） |

> **只想尽快出图**：用**火山方舟**或**通义万相**，填个 Key 就能用，不需要装任何命令行工具。
>
> **Google Gemini 通道是可选的**：它走本机的 Antigravity CLI（`agy`），需要能访问 Google、账号地区在支持范围内、且代理能路由到 Google 的 Code Assist 后端。**网络环境不具备时请直接用国内通道**，功能上完全够用。

这个插件原先叫 **柜体效果图**（`@local/dsh-cabinet-render`）。功能已经扩展到通用效果图，所以从根上改名为 **AI 效果图**：

| 项目 | 旧 | 新 |
|---|---|---|
| 目录 | `cabinet-render/` | `ai-render/` |
| 包名 | `@local/dsh-cabinet-render` | `@local/dsh-ai-render` |
| 插件名 / 行 id | `cabinet-render` | `ai-render` |
| 命令 | `/cabinet-render` | **`/ai-render`**（旧名保留为别名） |
| 标签页标题 | 柜体效果图 | AI 效果图 |
| 设置目录 | `<DSH_HOME>/cabinet-render/` | `<DSH_HOME>/ai-render/`（设置已自动迁移） |

| 环境变量 | `CABINET_RENDER_POLL_MS` | `AI_RENDER_POLL_MS` |

**柜体下单图仍然是它最擅长的用法之一**——底图类型里的「立面 / 施工图」就是为它准备的；只是现在它不再只是柜体工具。

## 一、怎么打开

两种入口，任选：

1. **右侧边栏标签页**：右侧栏的「+」里选「AI 效果图」，或点输入框工具行右侧的 **效果图** 按钮。
2. **对话里直接用命令**：`/ai-render {"provider":"ark","count":1}`，配合聊天附件里的底图与参考图。

面板和 Agent 走的是同一条宿主命令，行为完全一致。

## 二、首次配置：填 API Key

面板右上角点 **设置**，把 Key 粘进去，点「保存密钥」。密钥只写在本机：

```
C:\Users\Administrator\.dsh\ai-render\settings.json
```

也可以改用环境变量 `ARK_API_KEY` / `DASHSCOPE_API_KEY`（设置文件优先级更高）。

| 服务 | 去哪拿 Key | 说明 |
|---|---|---|
| **第三方中转站（OpenAI 兼容）** | 你的中转站后台 | 见下面「三、中转站怎么配」 |
| 火山方舟（即梦 Seedream） | https://console.volcengine.com/ark → API Key 管理 | 需要先在「开通管理」里开通 `doubao-seedream-4-0-250828` |
| 阿里云百炼（通义万相） | https://bailian.console.aliyun.com → API-KEY | 模型默认 `qwen-image-edit-plus` |

用哪家就配哪家，**至少配一个**。状态点：绿=已配置，黄=当前选中的服务没配 Key。

## 三、中转站怎么配（已实测 `direct.linkai.pics`）

面板「设置」里有独立一组字段：**base URL / API Key / 模型名 / 接口形态**。

1. **base URL**：中转站给的接口地址，填到 `/v1` 为止，例如 `https://direct.linkai.pics/v1`。只填域名也行，会自动补 `https://` 和 `/v1`。
2. **模型名**：不确定就点 **探测模型** 按钮——它会调 `GET /v1/models` 把模型列出来，点一下就填进输入框。
3. **接口形态**：默认「智能」，按模型名排序后逐个试，结果里会回报实际成功的那种。

### 接口形态一览

| 形态 | 请求 | 说明 |
|---|---|---|
| **异步任务**（智能模式首选） | `POST /v1/images/edits/async` → 轮询 `GET /v1/images/tasks/{task_id}` → 下载 `result.data[0].url` | **AILink 类站的主力通道**。参考图字段是 **`source_images`**；返回 `202 + task_id`，结果只有签名 URL，**没有 b64_json**；每个任务只出 1 张 |
| 异步（含 Gemini） | `POST /v1/linkai/images/edits/async` | 同上，但走 linkai 分组，支持 OpenAI / Gemini / Grok 模型 |
| 同步多图编辑 | `POST /v1/images/edits`，multipart | 部分站的遗留通道，容易 502；字段名见 `openaiImageField` |
| 同步文生图 | `POST /v1/images/generations`，JSON | 不带参考图时可用 |
| 对话出图 | `POST /v1/chat/completions` | Gemini 原生格式的站；图片在回复里，解析兼容 data URL / markdown / `images[].image_url.url` |

### 实测结论（`direct.linkai.pics`）

| 项 | 结果 |
|---|---|
| `GET /v1/models` | 只有 4 个模型：`gpt-image-2`、`gpt-image-2.5`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst` |
| **可用组合** | **`gpt-image-2` + 异步/同步 edits** ✅ 出图正常（40~55 秒） |
| `gpt-image-2.5` 走 edits | ❌ 502（上游报错，换 `gpt-image-2` 即可） |
| `image[]` 字段传多图 | ❌ 秒拒 503；要用重复的 **`source_images`**（异步）或 `image`（同步） |
| 带参考图的请求走 `/v1/chat/completions` | ❌ 400 This model is not supported on the Chat Completions endpoint |
| 同步 `generations` 带 `image` 参考图 | ❌ 秒拒 503 |

**本站推荐配置**（已写进设置文件）：

```json
{
  "openaiBaseUrl": "https://direct.linkai.pics/v1",
  "openaiModel": "gpt-image-2",
  "openaiMode": "auto"
}
```

### 三个必须知道的坑

1. **创建请求绝不能重试。** 文档原话：「创建请求不自动重试，避免重复生成并扣费」。插件因此在**任务一旦创建成功后就锁死**：后续轮询失败只会把原因和 `task_id` 报出来，**不会**再换别的形态重试。报错里的 `task_id` 请留着，可以据此查回任务。
2. **结果 6 天后过期。** `expires_at` 从创建任务起算 6 天，`temp_linkai_img/` 里的结果、参考图、蒙版到期返回 404。插件在出图当场就把图下载到本地目录，所以不会丢。
3. **参数名与同步接口不同。** 异步接口用 `source_images`（multipart 重复该字段，或 JSON 传 Base64/data URL 数组）**不接受 https 图片链接**；画质用 `quality`，模式用 `mode`（`text_to_image` / `image_to_image` / `edit`，本站图生图走 `image_to_image`）。

`gpt-image` 系列只接受 `1024x1024 / 1536x1024 / 1024x1536` 三个尺寸，插件会按 CAD 立面图的长宽比自动归到最接近的一个（实测 `1536x1024` 正常出图）；其它模型继续按比例传具体 `WxH`。

## 四、使用流程

1. **1 · 导入底图**：点选或直接拖入。底图**不一定是柜体立面**，按实际情况选「底图类型」：

   | 底图类型 | 适合什么 |
   |---|---|
   | 立面 / 施工图 | CAD 立面、施工图、节点图（带尺寸标注没关系） |
   | 手绘线稿 | 手绘稿、线稿、白模截图 |
   | 模型图 | SU / 3D 模型截图、素模（保持机位与透视不变） |
   | 实拍照片 | 现场照片，材质升级、去杂乱 |
   | 平面图 | 平面布置图 / 户型图 → 专业彩色平面图 |

2. **AI 读图出结构**（自动）：上传后视觉模型会读一遍底图，**按底图类型**列出结构清单，可手工修改——**这一步最影响「像不像」**，详见第五节。
3. **2 · 参考图**：1~2 张材质/颜色来源。建议裁到只剩材质，别把整间房照进去。
4. **3 · 底图类型与出图设置**：选风格预设、光影、构图，或点 **AI 润色提示词** 把大白话变成专业话术。
5. 点 **生成效果图**（多选风格 = 一次出多套方案）。通常 40~90 秒。
6. 对结果不满意就点 **改这张**，写一句修改意见继续迭代。

出图尺寸自动跟随底图的长宽比（长边最大 2048，16 的倍数），所以效果图构图和底图一致，方便直接给客户看。

### 用 @ 精确指定图片

提示词里可以 **@图片**，程序会自动翻译成模型能理解的图号：

| 你写 | 翻译成 | 含义 |
|---|---|---|
| `@底图` / `@原图` | 图1 | 结构依据那张 |
| `@参考图1` / `@参考1` | 图2 | 第 1 张参考图 |
| `@参考图2` / `@参考2` | 图3 | 第 2 张参考图 |
| `@木纹板.jpg`（可省扩展名） | 对应图号 | 直接写文件名也行 |

面板里参考图下方有一排 **`@底图` / `@参考图1` / `@参考图2`** 芯片，点一下就把提及插到「大白话」的**光标位置**——不用记编号。图像数量不够时对应提及会被忽略，不会误改。

同时提示词里会自动注入一行**图号对照**：

```
【图号】图1 = 底图（结构依据）；图2 = 参考图1。所有对图片的引用只按这些编号理解。
```

于是「`@参考图1` 的木纹换成深色，`@底图` 的结构别动」就能精确生效。斜杠命令里也一样：

```
/ai-render {"plain":"@参考图2 的台面换成岩板，其余不动"}
```

### 操作库（11 种「要做什么」）

一个操作 = 一套专用提示词（任务帧 / 结构措辞 / 视角 / 清理项都会换），读图提示词也跟着换。

| 操作 | 输入 | 输出 | 要不要底图 |
|---|---|---|---|
| 立面 / 施工图 | CAD 立面、施工图、节点图 | 实景效果图 | 要 |
| 手绘线稿 | 手绘稿、线稿、白模 | 上材质效果图 | 要 |
| 模型图 | SU / 3D 截图、素模 | 一键效果图（**保持机位**） | 要 |
| 实拍照片 | 现场照片 | 优化后的摄影级效果图 | 要 |
| 平面图 | 平面布置图 / 户型图 | 专业彩色平面图（彩平） | 要 |
| 平面→立体户型 | 平面图 | 3D 剖切轴测户型图 | 要 |
| 平面→透视效果图 | 平面图 | 人眼视角室内实景 | 要 |
| 分析图 | 平面 / 体块 / 效果图 | 体块 / 功能 / 流线 / 植物 / 软装分析图 | 要 |
| 风格迁移 | 白模 / 线稿 + 参考图 | 参考图风格套到你的方案上 | 要 |
| 换视角 | 任意底图 | 同空间另一个角度 | 要 |
| 文生图 / 灵感图 | 纯文字（可选参考图） | 概念灵感图 | **不要** |

### 结果上的一键操作（8 个）

出图之后不用重填表单，直接在结果卡片上点：

| 分组 | 一键操作 |
|---|---|
| 光影 | 换日光 / 换黄昏 / 换夜景 / 影棚光 |
| 氛围 | 氛围更暖 |
| 材质 | 按参考图换材质（用你上传的参考图替换材质，结构不动） |
| 视角 | 换 3/4 视角 |
| 清理 | 只清杂物 |

这些都是「改这张」通道的预设，**只改点名的那一项，结构、分格、五金位置一律不动**，所以不会把已经对的结构画坏。

### 菜单与操作严格对应

每个操作只显示**对它有意义**的控件。这是用户反馈「换视角下面还在选风格」之后做的全量核查——不只那一处，共发现 8 处错配：

| 操作 | 风格 | 光影 | 构图 | 读结构 | 自动质检 |
|---|---|---|---|---|---|
| 立面 / 施工图 | 家居 13 | ✅ | ✅ | ✅ | ✅ |
| 手绘线稿 | 家居 13 | ✅ | ✅ | ✅ | ✅ |
| 模型图 | 家居 13 | ✅ | ✅ | ✅ | ✅ |
| 实拍照片 | **沿用底图** + 家居 13 | ✅ | **✖** | ✅ | ✅ |
| 平面图 | 彩平 5 | **✖** | **✖** | ✅ | ✅ |
| 平面→立体户型 | 轴测 4 | **✖** | **✖** | ✅ | ✅ |
| 平面→透视效果图 | 家居 13 | ✅ | ✅ | ✅ | ✅ |
| 分析图 | 分析图 4 | **✖** | **✖** | ✅ | ✅ |
| 风格迁移 | **不选风格**（风格来自参考图） | ✅ | **✖** | ✅ | ✅ |
| 换视角 | **不选风格**（材质沿用底图） | ✅ | **✖** | ✅ | ✅ |
| 文生图 / 灵感图 | 家居 + 概念 16 | ✅ | ✅ | **✖** | **✖** |

每一处「✖」的理由：

- **换视角不选风格**：选了风格就会顺手换材质，「同一个空间换个机位」就断了。提示词改成「材质、颜色与表面工艺**完全沿用图1**」。
- **换视角不给构图选择器**：操作本身就是换机位，再给构图选择器是自相矛盾。
- **风格迁移不选风格**：风格完全来自参考图，再选预设只会互相干扰；并且**强制要求上传参考图**。
- **彩平 / 轴测 / 分析图不给光影**：它们没有方向性光照，「光照均匀、不设投影方向」已经写在风格里。
- **彩平 / 轴测 / 分析图不给构图**：正投影、轴测角是固定的，改了就不是这种图了。
- **照片优化不给构图**：换机位就不叫「优化」了；风格默认「沿用底图」（保持原样只提质），想改造再选家居风格。
- **文生图不给读结构、不给质检**：没有底图，两者都无从下手。

**质检判据也随操作切换**——拿柜体的「分格 / 门板 / 抽屉」去查平面图，模型只会胡报差异：

| 操作 | 质检判据 |
|---|---|
| 柜体类 | 分格数量、门板与抽屉的数量与位置、层板与横板的位置、整体比例 |
| 平面图 | 墙体位置与数量、房间划分、门窗洞口位置与宽度、**家具的种类与数量与摆放位置（特别注意有没有丢失家具）** |
| 平面→立体户型 | 是否与底图是同一个户型，有没有凭空增加或漏掉房间与家具 |
| 分析图 | 是否保持了设计关系，是否只叠加分析元素而没改动设计本身 |

### 风格预设按操作自动切换

**风格不是一套用到底的**——「平面图」不该看到「奶油风柜门」，「分析图」也不该看到「香槟金拉手」。所以风格按**组**划分，组再按操作分配，切换操作时风格列表**自动换**，并且当前选中的风格若不属于新操作，会自动切到该组第一个。

| 操作 | 风格组 | 预设 |
|---|---|---|
| 立面 / 手绘线稿 / 模型图 / 实拍照片 / 平面→透视 / 换视角 / 风格迁移 | **家居风格**（13） | 现代简约、奶油风、原木日式、极简纯白、轻奢、中古风、侘寂、轻法式、新中式、意式极简、工业风、北欧、跟随参考图 |
| 平面图 | **彩平风格**（5） | 柔光彩平（推荐）、木色彩平、分色彩平、水彩彩平、深色彩平 |
| 平面→立体户型 | **轴测风格**（4） | 白模轴测、陶土轴测、写实轴测、木色轴测 |
| 分析图 | **分析图风格**（4） | 极简线稿、扁平色块、高对比商务、手绘分析 |
| 文生图 / 灵感图 | **家居 + 概念**（16） | 家居 13 个 + 现代建筑外观、景观庭院、概念意象 |

风格组不同，**注入的段落也不同**——这是「彩平图很丑」那个问题的根因：

| 段落 | 家居 / 概念 | 彩平 / 分析图 | 轴测 |
|---|---|---|---|
| 材质段 | 【材质色彩】 | 【材质色彩】 | 【材质色彩】 |
| 细节段 | **【五金细节】**（拉手、门缝收口） | **【细节处理】**（线宽、色块边界） | 【细节处理】（剖切面、描边） |
| **画质段** | **摄影类**：8K、材质区分度、真实接触阴影、浅景深 | **图形类**：矢量级清晰、色块平涂、无材质纹理、**无摄影景深** | **中间档**：形体与剖切面清晰、材质简化 |

所以彩平图的提示词里**既不会出现「拉手」，也不会出现「专业室内建筑摄影」**。图形类操作拿到的是图形语言。

### 彩平图的制图规范写死在风格里

只写「彩平图」是没用的——实测会得到两种废图：**门窗只剩一个洞，家具只剩几个方块**。所以彩平风格必须把**制图符号长什么样**写出来，并且解开一个措辞矛盾：

- 【结构锁死】原先写「家具布置不得移动」，模型理解成「照着这几个方块原样复制」。
  现在改成：**位置、朝向、种类、数量不变，但图形表达要按制图规范重绘成标准俯视符号**。
- 【制图符号】段（彩平专属，优先级 94，不会被裁）逐条给出画法：

| 元素 | 画法 |
|---|---|
| 窗 | 在墙厚范围内画 **3 条平行细直线**（外墙断开处由窗线补上） |
| 平开门 | **门扇线 + 90° 开启弧线**，明确开启方向 |
| 推拉门 | 两段互相错开的平行细线；垭口只留洞 |
| 沙发 | 圆角矩形主体 + 后侧加宽靠背带 + 两端扶手方块 + **2~3 条坐垫分缝线** |
| 床 | 大圆角矩形 + 床头 **2 个枕头** + 被面翻折弧线 + 床头柜小方块 |
| 餐椅 | 小圆角方块 + **一条靠背短线**，朝向桌面均匀分布 |
| 橱柜 | 矩形 + 门板分缝线 + 台面出檐细线 |
| 洁具 | 马桶=椭圆+水箱；台盆=圆角矩形+内椭圆；浴缸=圆角矩形+内沿双线 |
| 地毯 | 圆角矩形/圆形浅色平涂块，压在沙发或床下方且略超出 |
| 绿植 | 俯视星形叶片簇，2~3 处点缀 |

另外彩平还带**专属负向词**：实景俯拍、照片、三维透视、立体、景深、材质纹理、木纹特写、阴影方向……防止模型又滑回照片。

### 机位：三个维度 + 图示卡片

机位不是一个扁平的下拉，而是**三个正交维度**——这是学竞品子菜单的做法（[献丑 3D角度](https://www.xianchou.com/docs/quick-start/image-node/3d-angle)、[Qwen-Image-Edit Multiple Angles](https://wavespeed.ai/blog/zh-CN/posts/introducing-wavespeed-ai-qwen-image-edit-multiple-angles-on-wavespeedai/) 的机位模型就是 8 水平 × 4 垂直 × 3 距离 = 96 种机位）：

| 维度 | 选项 |
|---|---|
| **水平角度**（方位角） | 原角度 / 正面 0° / 右前 45° / 右侧 90° / 右后 135° / 背面 180° / 左后 -135° / 左侧 -90° / 左前 -45° |
| **垂直角度**（仰角） | 原高度 / 平视 0° / 仰视 -30° / 俯视 35° / 鸟瞰 75° |
| **取景距离** | 不变 / 特写 / 中景 / 广角 |

三个全选「原样」时用操作自带的视角，不额外注入机位描述。面板里：

- **每一项都是图示卡片**（内联 SVG 画的示意图），不是文字芯片——水平角度画成俯视方位图、垂直角度画成侧视视线图、取景距离画成画幅与主体大小
- 顶部有 **「当前机位：右前 45° · 平视 · 中景」** 的实时组合显示
- 还有 **常用机位一键套用**：正视图 / 3/4 侧视 / 空间感 / 局部特写 / 高角度 / 反打机位

生成时拼成一句精确描述：

```
【视角构图】按指定机位重新取景：水平角度 45°（右前 45°）；垂直角度 0°（平视）；取景距离 中景。
镜头与主体平齐，透视自然。主体完整，保留少量周边环境。透视自然真实，材质、颜色、家具与图1完全一致。
```

> **为什么是图示卡片而不是文字芯片**：机位这种概念，文字（「微透视」「成场景」）表达不清，而一个小示意图一眼就懂。这也是竞品子菜单的共同做法。

### 子菜单一律是「图示卡片」

竞品的子菜单都是**图示卡片**（缩略图 + 标签），不是文字芯片——文字说不清「机位」「彩平」「流线分析」这种空间概念，一张小示意图一眼就懂。本项目全部改成图示卡片，示意图都是**内联 SVG**（不依赖任何图片资源，也不联网）：

| 子菜单 | 示意图是什么 |
|---|---|
| **机位·水平角度** | 俯视方位图：中间是主体方块，圆点是相机位置 |
| **机位·垂直角度** | 侧视视线图：地面 + 主体 + 相机高低与视线方向 |
| **机位·取景距离** | 画幅与主体大小（主体越小 = 取得越广） |
| **风格预设** | **该风格配色下的迷你柜体立面**；彩平组画迷你平面、轴测组画轴测体块、分析图组画色块+箭头、概念组画体量与绿植 |
| **分析图类型** | 五类各自的图形语言：体块堆叠 / 功能色块 / 流线曲线 / 树冠大小 / 家具色卡 |
| **光影** | 光源位置与色温：日光高挂、黄昏低角暖光、夜景暗底藏灯、影棚双柔光板 |

风格卡片靠**配色**区分；色卡缺失时会按风格 id 派生稳定配色，**不会退化成同一张灰图**。

> **离线自查**：`node tests/dump-icons.mjs && python tests/rasterize-icons.py` 把全部示意图画成一张对照图（`tests/out/icons-sheet.png`）。Agent 看不到真实面板，靠这个确认图标真的能看懂——第一版 13 个家居风格确实糊成了同一张灰图，就是这样发现的。

### 提示词的四个来源与优先顺序

提示词不是一份写死的模板 —— **材质、颜色、五金这些内容跟着图纸走**：

| 优先级 | 来源 | 负责什么 |
|---|---|---|
| 1 | **大白话（【本次要求】）** | 客户临时提出的、要覆盖后三者的要求 |
| 2 | **参考图** | 具体**纹理、光泽与色感**（长什么样） |
| 3 | **图纸（【图纸规定】）** | **材料种类、颜色、五金形式**（图纸标注了什么就是什么） |
| 4 | **风格预设** | 只在图纸与参考图都没写明的地方提供**风格基调** |

**关键**：「AI 读图出规格」不只是读结构，还会读出**图纸上标注的材质、颜色与五金**，作为硬约束写进提示词：

```
【图纸规定（已按图1识读，逐条必须满足）】
6. 材质与颜色：门板为白色亚克力，台面为黑色岩板
7. 五金与细节：明装黑色长拉手
以上是图纸本身的规定做法。凡是图纸写明的，一律照做，
不要用风格模板里的常见做法替换它。
```

于是材质段会变成：

```
【材质色彩】材料种类、颜色与五金形式以【图纸规定】为准；
具体纹理、光泽与色感以图2为准。
图纸未写明的部分，按以下风格基调处理：<风格预设的材质描述>
```

**不读图也能出图**，但材质颜色只能靠风格模板猜 —— 想「像图纸」就一定要点读图。

### 出图比例可以自己选

默认**跟随底图**（按图纸长宽比出图，构图最稳），也可以自己指定：

| 比例 | 适合 |
|---|---|
| 跟随底图 | 默认。构图与图纸完全一致 |
| 1:1 | 方形：产品图、封面、方版排版 |
| 3:2 / 2:3 | 相机横 / 竖构图（**gpt-image 原生支持这两种**） |
| 4:3 / 3:4 | 经典横 / 竖构图 |
| 16:9 / 9:16 | 视频封面、整墙全景 / 手机全屏、通顶高柜 |

**一个必须知道的事实**：比例能不能落地**取决于模型**。

- **gpt-image 系列只接受 1024x1024 / 1536x1024 / 1024x1536 三种**。选 16:9 会被归到 1536x1024（≈3:2）——**做不到真 16:9**。
- **即梦 Seedream / 通义万相接受任意 WxH**，选什么就是什么。

所以插件会**回报接口真实收到的尺寸**（而不是我们心里的那个），被归档时明确提示：

```
⚠ 你选的比例对应 2048x1152，但 gpt-image-2 只支持 1024x1024 / 1536x1024 / 1024x1536，
  已归到最接近的 1536x1024。想要精确比例请换即梦或通义万相。
```

**想要精确比例就换即梦或通义万相。** 面板里的比例卡片用小方框直观显示比例（跟随底图是虚线框 + 斜线）。

### 历史记录与参数复用

每次出图都会自动记一条历史（存在 `<DSH_HOME>\ai-render\history.json`），面板底部「历史记录」展开就能看到：

- **缩略图**、操作名、风格、时间、尺寸、模型、质检结论、耗时
- **还原参数**：一键把这一次的操作 / 风格 / 光影 / 构图 / 结构清单 / 大白话原文全部填回面板，改完直接再来一张——**不用重填**
- **改这张**：直接把这条历史的结果选为改图对象
- **清空**：只清列表，**磁盘上的图片不会被删**

几个实现上的取舍：

- 历史 JSON **只存参数与文件路径，不存图片**（图片本来就在磁盘上），所以文件很小
- 缩略图**按需读取**，且面板默认收起——避免一打开就读进几十兆
- 最多留 **80 条**，超出丢最旧的
- 历史文件**损坏不影响出图**：读列表时给出明确错误，出图后自动修复成合法结构
- 记历史失败**也不会丢掉出图结果**（图已经出了，那才是主要价值）

## 五、让结构像你的底图（最关键的一步）

**先说清原理**：`gpt-image-2` 这类是**画图模型**，不是视觉语言模型（VLM）。它**不会读尺寸、线型、图框**——它把你的底图当成一张像素参考图去模仿外观。所以「出的图不像我的底图」通常不是提示词写坏了，而是**输入喂错了**。

用真实图纸 A/B 出来的三个坑与对策：

| 坑 | 现象 | 对策 |
|---|---|---|
| **黑底白线图纸** | 模型被暗底带向深色画面，白细线也不构成「设计图」语义 | 面板 **「黑底图纸自动转白底线条」**（默认勾选）：自动判断平均亮度并反相，线条压纯黑、底压纯白；读图时也要求图够大够干净 |
| **一张图里多个视图** | 俯视/正立面/侧剖混在一起，模型不知道该渲染哪个，容易三者混合 | 上传后点 **裁切**，只框**正立面**本身，把图框、标题栏、其他视图、周边空白全部裁掉 |
| **参考图是完整房间效果图** | 模型**照抄参考图的构图**，把别人的房间、家具、水印一起画进来 | 参考图也点 **裁切**，只框**材质/颜色区域**；提示词里还会显式加一句「只取材质，绝对不要复制其构图、家具、房间布局、人物或水印」 |

**推荐流程**：

1. CAD 截图/导出图 → 上传 → **裁切**到只剩柜体立面（留少量尺寸标注没关系，提示词要求清除）
2. 确认 **黑底自动转白底** 已生效（缩略图下方会显示「已转白底」）
3. 参考图 → 上传 → **裁切**到只剩材质颜色（尤其别把整间房照进去）
4. 选风格预设（或「跟随参考图」）→ 生成效果图

做完这三步，结构还原度是**量级差别**——这是拿真实图纸实测出来的，不是猜的。

### 让模型真正「读懂」图纸：AI 读图出结构

上面说的是「喂对图」。但图片模型终究只会模仿像素，**不会数门板**。真正的解法是让**视觉模型**先读一遍 CAD，把结构变成文字清单，再作为硬约束注入提示词：

```
CAD 图 → 视觉模型读图 → 「左 200 通高侧板；右 816 主柜；上部三层板；
                          中部 650 开放区；一道横板；下段 644 开放区」
       → 注入【图纸结构】段 → 出图
```

面板里有这个功能：

1. 上传 CAD 后**自动读一次**（可关），或点 **AI 读图出结构**
2. 读出的清单显示在可编辑的框里，**你可以直接改**
3. 生成时它作为 `【图纸结构（已按图1实测，逐条必须满足）】` 段注入，优先级仅次于「结构锁死」

**用的是会话里当前的多模态模型，不需要额外开 Key。** 本机实测：DSH 配的默认模型 `deepseek-flash`（DeepSeek-V41-Flash）在模型目录里声明了

```js
inputModalities: ["text", "image"]
```

即**本来就是多模态**。插件先用 `llm.resolveModelInfo()` 确认该模型收图，不收就明确报错，不会静默退化成文字占位符。

> 补充两个实现细节：视觉编码是 544×544 起上采、14px patch、单图上限 1024 tokens，所以**送进去的 CAD 要够大够干净**，小字细线才读得出来——这正是前面「裁切 + 转白底」的另一个用处。
> 如果将来把默认模型换成不支持图像输入的模型，这一步会报错提示你换模型；出图本身不受影响。

读不出来或不满意时，面板的**「大白话」框**可以手填结构要点，效果接近：

> 「左侧 200 通高侧板；上部三层板；中部 650 开放格放书；一道大理石横台；下段开放」

## 七、预设提示词与智能体

提示词按 **7 段式专业话术**组装，这套结构学自 Evai建筑大师（openevai.com）「提示词大师」的专业话术范例，并按建筑学长AI（jianzhuxuezhang.com）按用途分智能体的思路拆成任务模式。文案是按该结构自己重写的，不是照搬。

```
任务帧         把图1的CAD立面图渲染成照片级写实的实景效果图
【结构锁死】    几何、比例、分格、门板与抽屉的数量位置一律不得改动   ← 硬约束，永不裁掉
【视角构图】    正面平视一点透视，机位与构图与图1一致
【材质色彩】    风格预设的具体材料名与表面工艺（+ 参考图为准）
【五金细节】    拉手形式、3~5mm 阴影缝、收口
【空间环境】    墙面、地面、陈设
【氛围】        三到五个形容词收尾
【光影】        光源方向、色温、明暗关系
【画质】        8K、材质区分度、专业室内摄影、无文字水印
【清除】        尺寸线、数字、标注、引线、图框、辅助线
【补充要求】    你自己的话（永远放最后）
```

### 操作库

11 种操作（每种一套专用提示词）与 8 个结果一键操作，见第四节的两个表。
### 风格预设（13 个）

现代简约 · 奶油风 · 原木日式 · 极简纯白 · 轻奢 · 中古风 · 侘寂 · 轻法式 · 新中式 · 意式极简 · 工业风 · 北欧 · 跟随参考图

每个预设都带**具体的材料名与表面工艺**（例如奶油风是「奶油白与米杏色哑光烤漆，边角做小圆弧过渡，台面为同色系浅色岩板」），而不是「好看的材料」这类空话——这是效果图能不能用的关键。选中风格后，材质描述会与参考图叠加：**参考图定材质，预设定风格方向**。

另有 **5 个光影预设**：跟随风格 / 自然日光 / 黄昏暖光 / 夜间氛围灯 / 影棚光。光影预设会覆盖风格自带的光影描述。

### 大白话 → 专业话术

面板里「大白话」框写人话（例如「客户想要奶油风，柜门不要拉手，台面要深色岩板」），点 **AI 润色提示词**，宿主编会调 DSH 的 llm 服务把它改写成上面那种分段专业话术，写进一个可编辑的框里。润色结果会**原样作为提示词发送**，你也可以直接手改。

> 注意：这一环只做**文本改写，不看图**（当前默认模型是文本模型，没有视觉能力），与 openevai 的「提示词大师」同性质。润色失败会自动退回内置模板组装，不会阻塞出图。

### 多方案

风格预设**可多选**，选 3 个就是一次出 3 套方案（异步接口一个任务只出一张，所以是逐个出，进度会显示「正在出第 2/3 张」）。

### 迭代改图（画布式 agent 循环）

每张结果下面有 **改这张** 按钮。点它，再写一句「想改什么」（例如「柜门换成浅色原木格栅，五金改为隐形无拉手，其余不动」），出图时会把**上一版效果图当图1**，提示词切成改图模式：

```
在图1这张已有效果图的基础上做定向修改。
【结构锁死】除点名改动外，结构、分格、数量位置、机位与构图全部不变，不得重新设计。
【本次改动】柜门换成浅色原木格栅，五金改为隐形无拉手
【材质色彩】除【本次改动】点名的部分外，其余材质沿用图1，不要整体换风格。
```

可以反复迭代，每一版都存成独立文件。改图模式**刻意不复述风格材质**——否则会出现「要求把柜门换木纹」与「复述里写着奶油白烤漆」自相矛盾的情况。

### 长度预算

即梦 Seedream 官方建议提示词 ≤300 汉字。插件对 ark 自动启用 300 字预算：超长时先用精简文案，再按优先级丢段（五金 → 空间 → 氛围），但**结构锁死、材质、本次改动这些硬约束永不裁掉**。其它 provider 不限长。

### 覆盖方式

想完全用自己的提示词，在 config 的 `promptTemplate` 里写死（`{refs}` 会替换成「图2」）。面板里 AI 润色过或手改过的提示词优先级更高，会原样发送。

## 八、成本与耗时

- 计费按**成功出图张数**，失败调用通常不计费。
- 火山的 2K 出图单张约一角到几角；百炼同量级；中转站看它自己的定价。张数＝成本倍数，先用 1 张试。
- 单次超时默认 **600 秒**（异步任务要排队 + 轮询），可在 config 里改 `timeoutMs`。
- 中转站异步任务实测单张约 **40~55 秒**。

## 九、出问题时

| 现象 | 原因 / 处理 |
|---|---|
| `还没配置…API Key` | 面板「设置」里填 Key 并保存 |
| `还没填中转站的接口地址` | 面板「设置」里填 base URL |
| `接口调用失败（HTTP 401）` | Key 写错、或该服务没开通这个模型 |
| 中转站报 `404` | base URL 少了 `/v1`，或该站没有这个接口路径 → 换一种「接口形态」 |
| `创建任务失败（HTTP 502）` | 上游临时故障，或该模型不支持这个通道（`gpt-image-2.5` 在这家站就是 502，换 `gpt-image-2`） |
| 带参考图的请求秒拒 `503` | 字段名不对。异步要用 `source_images`（插件已按文档实现），同步要用 `image` 而不是 `image[]` |
| `任务失败（task_id=…）` | 上游出错。**task_id 留着**，可据此向中转站查回；插件不会自动重发（防重复扣费） |
| 换 Gemini/即梦就报错 | 把「接口形态」切到 **异步（含 Gemini）** 或 **对话出图** |
| 结构被模型改动 | 补一句「严格保持分格结构不变」；或换 Seedream / `gpt-image` |
| 输出还是带尺寸线 | 补一句「去掉所有尺寸标注与文字」，或提高出图边长（config `maxSide`） |
| 面板点生成没反应 | 刷新页面（插件前端改动后需要重新加载） |
| 出图时报 `IMAGE_OFFLOAD_REQUIRED` 之类 | 图太大，先把 CAD 截图裁到只看柜体 |

## 十、结构说明（给维护者）

```
ai-render/
├── package.json       # dsh.bundle.patch + dsh.client（platform: web）
├── cordis.patch.yml   # 插入 ai-render 行，附默认 config
├── index.js           # 宿主端：命令 + 三家图像 API + 异步任务轮询 + 落盘 + 设置 + LLM 润色
├── presets.js         # 预设库：3 任务模式 / 13 风格 / 5 光影 + 7 段式提示词组装器
├── client.js          # 浏览器端：右侧标签页 + 快捷按钮 + 预设选择 + AI 润色 + 迭代改图
├── tests/             # 离线回归 + 真实出图 + 中转站诊断（见第十节）
├── icon.svg
└── locale/{zh,en}.json
```

三条关键设计：

1. **零外部依赖**。宿主编刻意不 import 任何包（包括 `@deepseek-ai/schemastery`）：workspace 链接的插件解析不到 dsh 内置包，一旦 import 失败整行插件就起不来。因此参数校验手写，可调项走 `cordis.patch.yml` 的 config + 设置文件。
2. **全走框架已鉴权的 Remote 通道**，不注册裸 HTTP 路由：
   - 面板 → 宿主：`ctx.remote.commands.execute(sessionId, '/ai-render <json>', 图片附件)`（命令声明 `input.attachments: true`，图片由附件服务持久化并校验）
   - 结果回显：宿主落盘后回绝对路径，面板用 `ctx.remote.workspaceFiles.readBytes(sessionId, 路径, {})` 取字节转 Blob URL
   - 两个方法的 `signal` 都由 Typert 传输层注入，调用方不传；返回值是 `{ ok, value }` 信封
3. **三家 provider 同一个 `generate()` 出口**，只有请求构造与响应解析分开；中转站的形态收敛在 `callOpenAi*` 里，异步任务用 `TaskNotSettledError` 把「已创建、不可重试」这条规则钉死。

## 十二、还没做的（下一步可以加）

- **DWG 源文件**：目前只支持图片/PDF 导出的位图。要做 `.dwg` 需要先接 CAD 渲染（ODA / 本机 CAD 导出），工作量大一个量级。
- **局部重绘（蒙版画笔）**：竞品的「AI局部重绘」。中转站异步接口已支持 `mask_image`，但要做「涂哪里改哪里」的画笔交互 + 结果对齐，是第二批里最大的一块。
- **展板设计**：竞品有 40 套模板。**建议本地拼版**（用 Pillow 把效果图 + 彩平 + 色卡 + 标题排成展板），不花生成费、排版还准确——比让图像模型写字靠谱得多。
- **图转 3D / 漫游视频**：需要专门的 3D 与视频生成模型，中转站只有图像模型，⛔ 做不了。
- **多角度「完全一致」**：竞品标榜多角度一致，本质靠 3D 保证。图片模型只能做到「看起来是同一个空间」，做不到几何级一致，别对客户承诺这一点。
- **材质库 / 历史记录**：常用板材裁好存起来一键复用；出图参数与结果留存可回滚。
- **画布：多图接力**：结果栏保留本轮全部候选，点任意一张作为下一轮输入。
- **视觉质检自动重试**：现在能读图出结构，但还不能「出图后自动看图打分 → 不合格自动重出」。视觉模型既然可用，这一条可以补上。
- **多视角批量**：一次上传正立面 + 侧立面 + 节点图，按视角批量出图。
- **预设库可视化编辑**：现在改预设要改 `presets.js`；可以在面板里加一个预设编辑器（存进设置文件）。
- **参考图库 / 历史记录**：把常用的样板参考图存成「材质库」，一键复用。
- **Agent 工具**：现在 Agent 能通过 `/ai-render` 命令调用；可以再包一个 `cabinet_render` 工具，让它能自己决定风格预设与迭代。
